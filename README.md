# GONER PACK 014 — обучаемый словарь OCR

Поверх версии 013 (PP-OCRv5 + резервный Tesseract) добавлен **словарь исправлений, подтверждаемых сборщиком**.

1. На экране проверки чека выберите верное название из справочника или отредактируйте его вручную. Если исправление соответствует существующему блюду, появляется кнопка «🧠 Запомнить исправление». Без нажатия правило не записывается.
2. Исходное прочтение OCR → выбранное блюдо сохраняется в IndexedDB (`gonerpack`, хранилище `learn`, версия схемы 3). При следующем точном совпадении исходного прочтения приложение подставляет подтверждённое имя; показывает пометку «исправлено по вашему словарю».
3. Через **Справочник → История исправлений** можно увидеть, какие пары сохранены, удалить отдельное правило или очистить все.
4. При конфликте с точным названием/алиасом **другого** блюда правило не создаётся и не применяется. Если блюдо удалено, правило не работает; это видно в истории. Неизвестные блюда автоматически не переименовываются. Количества, номера и суммы правило не меняет.
5. Для сомнительных названий предлагается до трёх вариантов; рекомендации не заменяют текст сами, численно несовместимые названия отбрасываются.

**Обновление:** распаковать архив поверх старой папки сайта и загрузить содержимое в корень репозитория GitHub Pages. Сохранённые в браузере заказы, фото и справочник должны пережить миграцию IndexedDB 2→3; перед обновлением рекомендуется проверить данные и не очищать память сайта. Новый словарь локальный: между Firefox и Chrome не синхронизируется.

**Проверки:** `node --test tests/learning014.test.js` (проверка словаря, конфликтов и миграции схемы); прежние тесты: `node --test tests/parser.test.js` и другие. В реальном Firefox на Android версия 014 пока не проверялась.

# GONER PACK 013 — Neural OCR

Новый движок распознавания: **PaddleOCR PP-OCRv5** — поиск строк `PP-OCRv5_mobile_det` + распознавание `eslav_PP-OCRv5_mobile_rec`
(русский/украинский/белорусский, латиница, цифры). Лицензия моделей Apache-2.0, размер 8.8 МБ (`models/`, подробности и SHA-256 — `models/README.md`).
Выполняется в браузере через **onnxruntime-web 1.20.1** (MIT), WebAssembly, без сервера и платных API; фото не покидает телефон.

- `neural.js` — предобработка, поиск строк (DB-карта → компоненты), исправление наклона (проекционный профиль), распознавание строк, CTC, раскладка по строкам с координатами.
- `neural-web.js` — загрузка onnxruntime-web и моделей в браузере. **Не проверен на телефоне.**
- Структуру чека (блюда, количества, суммы, приборы, номер, доп. ID, многострочные названия) собирает прежний разбор 012 + справочник; нейросеть блюда не придумывает.
- Движок по умолчанию — нейросеть. Tesseract 012 сохранён: переключатель «Движок», кнопка «Сверить резервным Tesseract» (если нейросеть не подтвердила итог), автоматический переход, если нейросеть не загрузилась.
- `lab.html` — **OCR LAB**: сравнение Tesseract 012 / Neural 013 / комбинированного на ваших фото с эталоном (1043264, 1043361, 1043362, свой); разбор вставленной диагностики.
- Результаты сравнения — `RESULTS-013.md`. Конвертер TFLite→ONNX — `tools/neural/`.

Тесты: `node --test tests/*.test.js` — 186 (из них на реальных фото через ONNX Runtime: `tests/neural.test.js`). Сравнение: `node tests/variants013.js`.

# GONER PACK 012

## Что нового в 012 (относительно 011)
Основа: реальная диагностика Android и фото чека №1043264 (`tests/fixtures/diag-1043264.txt`, `receipt-1043264.jpg`, эталон `receipt-1043264.truth.json`).
- **Строки не теряются в разборе.** Количество «1.0», которое Tesseract.js на телефоне читает как `‚0`, `{0`, `{1,0`, `10`, `140`, `\.0` или слипшимся с суммой (`‚070,59`), распознаётся как 1 с пометкой «неуверенно». Частично прочитанная сумма (`21.%`, `169:`, `118.0`) не выкидывает строку: сумма отмечается как непрочитанная.
- **Многострочные названия.** Продолжения «СЫРНОМ СОУСЕ», «В СЫРНОМ СОУСЕ», «(5 шт)» присоединяются к своему блюду даже с заглавной буквы и через шум слева/справа; строка с количеством и суммой продолжением не считается. Шум слева от названия («Же | …», «ий     ТОРИ…») отрезается.
- **Объединение проходов переписано.** Строки выравниваются по порядку таблицы (как выравнивание последовательностей) с учётом названия, справочника, суммы и позиции. Строки, которые справочник относит к разным блюдам (краб ≠ креветка), не сливаются. Количество и сумма — голосованием; итог чека только проверяет (может выбрать между реально прочитанными суммами или подтвердить строку из одного прохода), но не придумывает позиции.
- **Доп. ID**: голос прохода весит по его надёжности (доля сумм, совпавших с итоговыми), учитывается позиция строки (над приборами, под номером) и длина как у номера предчека.
- **Приборы**: «Ложка», «Вилка», «Нож и вилка» — отдельно, как на чеке; нечитаемое количество не теряет прибор.
- **Справочник**: 167 позиций (+13: блюда чеков 1043361 и 1043264 и «Вилка»), ничего не удалено.
- **Экран проверки**: компактное фото (увеличение по нажатию), полные названия (многострочное поле), кнопки переносятся и не выходят за экран, повторяющиеся предложения OCR убраны, закреплённая кнопка с компактным счётчиком «✓ N из M · осталось проверить K» не перекрывает содержимое, расхождение номера/ID показано прямо у поля.

Тесты: `node --test tests/*.test.js` — 169. Новые: `real-1043264.test.js` (реальные тексты телефона), тесты на реальных изображениях обоих чеков (нативный Tesseract), юнит-тесты разбора/начинок, UI-тесты на экране 360 px. Замер: `node tests/measure012.js`.

# GONER PACK 011 (предыдущая версия)

## Что нового в 011 (относительно 010) — ложные позиции и объединение проходов
Основа: реальная диагностика Android чека №1043361 (`tests/fixtures/diag-1043361.txt`, не изменена).
- **Таблица.** Позиции берутся только из таблицы (между «Наименование / Кол-в / Сумма» и итогами). Если заголовок не распознан, фрагменты строк вообще не склеиваются, а итог сверяется по «к оплате». Шапка, «ОНЛАЙН-КАССА», «японская & европейская кухня» (`hdrish`) не могут стать блюдом или его частью. Мусор OCR (`nameish`) не склеивается и не попадает в «пропущенные строки».
- **Переносы названий.** Склеиваются только внутри таблицы: продолжение со строчной буквы или обрыв на предлоге. Несовместимые фрагменты показываются на проверку, названия не «сочиняются».
- **Выбор лучшего прохода** по структуре и согласованности (заголовок, сошедшийся итог, чистые названия, штраф за мусор и потерянные строки), а не по числу строк.
- **Объединение проходов.** Строки сопоставляются по сумме, при расхождении — по вертикальной позиции и количеству. Выбираются только существующие «похожие на название» прочтения; достоверная строка лучшего прохода сохраняется (меняется лишь на подтверждённую справочником или единодушную близкую версию двух+ других проходов). «Другие прочтения» — только близкие к выбранному названию. Приборы: количество по большинству.
- **Доп. ID** читается при шуме справа/слева от числа (`4830390:   ь`), голосование проходов выбирает 4830390, а не 1830390.
- **Приборы** отдельно; «нож и вилка» — отдельная позиция «Нож и вилка».
- **Диагностика** теперь показывает число слов с рамками и способ разбора (текст/геометрия) — это нужно, чтобы узнать, отдаёт ли Tesseract.js на телефоне координаты слов.

Тесты: `node --test tests/*.test.js` — 139. Новые: `tests/real-1043361.test.js` (реальные тексты Android через настоящий конвейер), юнит-тесты правил, UI-тест. Не проверено на настоящем Android: см. отчёт.

# GONER PACK 010 (описание предыдущей версии)

Мобильное веб-приложение (PWA) сборки заказов доставки по фото предчеков. Работает на телефоне, данные хранятся только в нём (IndexedDB).
Распознавание — Tesseract.js в браузере, фото на сервер не отправляется (при первом запуске скачиваются библиотека и модель, нужен интернет).

## Что нового в 010 (относительно 009)
- **Единый справочник** (`dict-seed.js`, 154 позиции: 148 из Excel + 7 названий из эталонных чеков ТЗ; «Кацудон»/«Кацу-дон» слиты). Это **стартовый набор, не полный список**: блюдо, которого нет в справочнике, остаётся с текстом OCR и просит одного нажатия.
- **Хранение**: встроенная база в коде + правки пользователя в IndexedDB (`dict`): добавленные, изменённые, удалённые (надгробия). Схема БД не менялась (v2), записи 009 читаются.
- **Управление**: добавить, изменить (название, раздел, алиасы), удалить, «Вернуть встроенный», **импорт .xlsx (все листы) / CSV / TXT без интернета** (свой читатель zip+XML, без SheetJS), экспорт CSV.
- **Сопоставление названий** (`matcher.js`): нормализация (регистр, ё/й, латиница и цифры вместо букв, значки `@ ©`, пробелы/знаки), взвешенный Левенштейн с дешёвыми OCR-путаницами (у/ч, и/н, е/с…), сходство слов без учёта порядка, слитые/разорванные слова, алиасы.
  - *Высокая уверенность* → название заменяется на справочное, показано «Распознано: … → исправлено», подтверждать не нужно.
  - *Средняя* → исходный текст остаётся, предлагается замена одним нажатием.
  - *Низкая / нет в справочнике* → исходный текст остаётся, пометка «Нет в справочнике» или «Похоже на ошибку распознавания».
  - **Защита**: автозамена только если каждое значимое слово нашло пару, числа/объёмы совпали и лидер заметно лучше второго. «Суши острые с угрём» не превращается в «…с тунцом/креветкой».
- **Распознавание**: пересборка строк по геометрии слов (рамки Tesseract), выбор лучшего из двух разборов прохода; **объединение проходов** (строки сопоставляются по сумме; название — из справочника или медоид; пропущенная строка добавляется только если после этого сошёлся итог чека; расхождения помечаются); отдельный **проход по таблице** (полоса между заголовком и итогами), если ни один проход не сошёлся с итогом.
- **Экран проверки**: сводка «Блюд / в справочнике / нужна проверка», поиск по справочнику для исправления названия, другие прочтения OCR, «Оставить как есть» одним нажатием (и пакетно), «Создать заказ» активна только после проверки сомнительных позиций; правильно распознанные блюда подтверждать не нужно.
- **Исправлено**: `lead()` отрезал настоящие короткие слова в начале названия («Иг ай яки» → «яки»).
